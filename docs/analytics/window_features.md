# Window Features

`mmla ses-fuse` turns a session's events (what the ASR, IPS and VFA pipelines stored in InfluxDB, see the [Database Reference](../database.md#influxdb)) into one table, the fusion table, one row per window (10 s by default), with the speech, space, body, gaze and action features side by side and a coverage count per modality:

```bash
mmla ses-fuse -c pipelines/vfa-base/config.yml -sid <session-id>                       # from InfluxDB, through any config with an InfluxDB section
mmla ses-fuse --measurements artifacts/<session-id>/measurements -w 10 -st 10 -o features.csv   # from an export
```

Persons are tag ids (`-tags 0,1` names them, and they are then the session's pupils too; else the tags the events hold), pairs are sorted tag pairs; persons the pose model saw without a tag count only in the seat trace. A cell is empty when its modality contributed nothing to the window. The table lands in `artifacts/<session>/analysis/features/` with an analysis record next to it saying which events it came from; the export folder's `<session>_features.json` is the `vfa_features` events. Before any window is cut, the fusion remakes the gaze targets with the current [hand circle](#the-hand-circle-remade), labels each camera's [work area](#the-work-area) and carries the tags [along the tracks](#tags-along-the-tracks), in that order.

## Tags along the tracks

The features endpoint keeps a read tag on its track from then on (`tag_match: track`, see [Pose](../pipelines/vfa/index.md#pose)), however long, but not backwards, and not once the tag was read on another track. A track that lost its person and was picked up by another body carries the tag on to the wrong person, sometimes for minutes. So the fusion first trusts a kept tag for 60 s (`TAG_MEMORY_SECONDS`) after the track last read it and takes it off later frames, as it does a kept tag the track never read or whose last read was another tag: the person is an untagged body again (`person_id` `track_<id>`), and the frame's pairs and gaze targets follow the new name (`expire_track_tags`). This comes before the work areas, the seats and the pupils' tracks learn from the tags. In five replayed sessions the next read on the same track confirmed a kept tag in 86 % of the frames within 5 s of the last read, in 69 % at 45 to 60 s and in about half after a minute, and contradicted it in about 2 % up to two minutes and in 7 to 22 % beyond. At 60 s the cleaner sessions keep 87 to 97 % of their tagged frames; a session that leans on the memory loses up to 30 %, and a pupil seen mostly through it is absent in more windows.

Before any window is cut, the fusion then carries the tags over the whole session, per camera: a tracked person without a tag, on a track that read a tag at most 60 s before or after, takes the tag of that track's nearest read (the earlier one on a tie) and is marked `tag_match: propagated`, with `person_id` the tag and the frame's pairs and gaze targets renamed to it. So the frames before a track's first read are named, and a track that read two tags is split between them where each untagged frame is nearer to one read or the other. A read tag, and a tag the server kept within the minute, are never changed. A tag is not given in a frame where another person already carries it, nor to two tracks in one frame (neither gets it), and a track id that appears twice in one frame names nobody. A track id not seen for more than 60 s (`TRACK_GAP_SECONDS`) counts as a new track, because ByteTrack keeps a lost track for 30 frames (30 s at one frame set a second) and a longer absence means the id was handed out again. A propagated person counts like a tagged one in every column, and the seat trace counts only the bodies still untagged after it; the seats themselves are learned without the propagated boxes, so a track carried to the wrong person does not move them. A track that never read a tag stays untagged, and so does a stretch of a track more than 60 s from its nearest read. `window_features(..., track_tags=False)` builds the table without the propagation, and so does one from events without `track_id`. `mmla ses-fuse -tm 0` (`window_features(..., tag_memory=None)`) keeps every kept tag and carries the reads without a limit, as every table fused before 2026-10-02; `-tm 30` trusts a tag for 30 s. The analysis record says which (`tag_memory_seconds`, null for no limit).

## Pupils

A partner is another pupil of the session. The pupils are the `-tags` given to `mmla ses-fuse`, else the `pupils` the session's `manifest.json` declares (`mmla ses-tidy --pupils`), else the tags up to 12, the IPS trust bound (a higher one is a misread badge). The command prints them with their source and writes them into the analysis record (`pupils`, `pupils_source`). A gaze target is in the group when its `person_id` is a pupil's tag after the tags were carried along the tracks, so a pupil the server knew only as `track_8` counts once the fusion named the track. A target that stays untagged after that is still a pupil when its box centre stands at the seat (on that camera, the seat of the seat trace above) of a pupil whose tag the frame does not hold: the badge was not read, and nobody else sits there. Without the rule these frames go to `other_*` and the partner shares are short. What stays `other_*` still includes a pupil with an unread badge away from their seat, so the rule lessens that error but does not remove it. `n_vfa_seat_partners` counts the gaze frames named by the seat. `window_features(..., seat_partners=False)` leaves every untagged target as someone else. Who is someone outside the group for the joint split and the `nm_*` columns (a non-member) is ruled on separately, below.

## The work area

A gaze on the shared table, a microscope or a tablet lands on no face and no hand, and the server calls it `elsewhere`, together with a gaze at the floor or at the next table. Before any window is cut, the fusion learns, per camera of the session (and frame size), where the pupils' hands have been, and calls an `elsewhere` gaze that lands there `work_area` (`openmmla/services/vfa/work_area.py`, `label_work_areas`). The area is the box between the 2.5th and 97.5th percentile (nearest rank) of the pupils' hand centres on each axis, grown on every side by the median hand radius (the hand circles the server scores, 0.4 shoulder widths) and by the gaze tolerance every target gets (the longer side / 64), and clipped to the frame. It is ready from the 200th hand sighting (five sightings beyond each 2.5 % edge; about 40 to 60 s with two or three pupils at one frame set a second). It is causal and cumulative: a frame is labelled with the hands of the frames up to and including it, never later ones, so the same frames in the same order give the same labels offline and online. It learns only from the tags the server gave (read or kept on the track), never the propagated ones, so a track carried to the wrong person cannot stretch it, and only from the pupils' hands, never the teacher's. Faces, hands, zones, `out_of_frame` and `unknown` keep priority: only `elsewhere` is relabelled. That matters, because in 2D the area is not free of faces (a partner's face above the table falls inside it), so the area works only because faces and hands are scored first. A frame that already carries `work_area` (a server that labels online) is kept as it is. Weak spots: a camera on the edge of the group that sees no pupil hands is never or rarely ready, so its `p<tag>_work_area_ready_ratio` is low; and on a camera close to the table the area covers a large part of the frame. Padding by the hand radius matters on a microscope side camera, where the eyepieces sit just beyond the hands on the focus knobs. Early areas are smaller, which errs toward fewer relabels.

## The hand circle, remade

Every `vfa_features` event stored before the server's image was rebuilt for version 2 was made with version 1 of the [hand circle](../pipelines/vfa/index.md#pose) (0.14 shoulder widths past the wrist), and version 2 (0.33) moves which hands a gaze lands on and how far apart two persons' hands are. Before anything else, the fusion makes every frame's gaze targets and pair hand distances again from what the frame stores: the keypoints and boxes, `face_bbox`, the gaze's point and `inout`, the zones, the frame's size, and the thresholds the frame states in `scoring`, else the server's defaults, a `keypoint_confidence` of 0.3 and an `inout_threshold` of 0.5 (`relabel_hand_circles`, with `features.relabel_answer` per frame). No video is replayed. It runs on the frames as the server named them, so it comes before the tags are carried along the tracks, and before the work area, which relabels only `elsewhere` gazes and learns from the same circles. The rest of the frame is kept, the gaze distances too. A frame that cannot be remade (no size, a person without keypoints, a box or a name), a frame that already carries `work_area` and a frame the server already made with the circle asked for (its `scoring` says so) stay as stored, as does the target of a person with a gaze point but no face box. With the version 1 circle the remake gives back the server's answers, but for a few targets and distances that the rounding of the stored numbers moves (coordinates ±0.05 px, confidences and `inout` ±0.0005), such as a keypoint whose stored confidence rounds onto 0.3 or an `inout` that rounds onto 0.5. With version 2 more gazes land on hands, a person's own or a partner's, and fewer on the work area, which only takes what the hands leave `elsewhere`. `mmla ses-fuse -hr false` (`window_features(..., hand_relabel=False)`) keeps the stored targets and distances, and the work area and the hand columns then read the circle the frames were made with (version 1 for a frame without `scoring`), so every column the table had before the change keeps its value; the analysis record says which circle a table used (`hand_circle`: `version`, `relabelled`, `nudge_radii`, `radius_shoulders`, `stored_frames`, the frames by the circle the server made them with, and the thresholds that stand in for a frame that states none).

## The hands in body units

The wrist speed and hand distances above are in frame widths, so a pupil nearer the camera, or a camera standing nearer the group or with a narrower field of view, moves faster and further; the pixels themselves cancel out. The columns added on 2026-09-24 measure the hands in body units. Each pupil's wrists are followed in the image, and each move is measured in the pupil's own shoulder widths (the mean of the two frames'), from one frame set to the next on one camera, reading only wrists and shoulders seen with confidence 0.5 or more. A step is two frame sets in a row, 0.75 to 1.5 s apart, that both hold the pupil, and only one body with the pupil's tag, on the same camera: in a frame set where two bodies wear one tag (a track's remembered tag and a read one) the step cannot tell which body it follows. The bounds below are moves in a 1 s step (one frame set a second), so a session at another cadence (a `keyframe_interval` of 0.5) has no hand steps, and empty hand columns, until the bounds are measured for it. A step is **active** when a wrist moved at least 0.16 shoulder widths, **still** when every wrist seen moved less than 0.08, and neither in between. The still bound sits at the 90th percentile (p90) of the move of a wrist whose arm stayed still in the image (its own elbow and shoulder each moved under 0.05 shoulder widths; nothing is subtracted, and the wrist itself is not in the definition, so its spread is not cut), and active is twice the still bound. That p90 is a convention of the definition, not the keypoints' noise alone: it rises with the arm's bound, since a looser arm lets real movement in, and one still step takes in arms that are just stopping or about to move. A step takes the largest of its wrists' moves. A hand's length (wrist to farthest fingertip) is taken as 0.46 shoulder widths, from the confident hands of the whole-body model the [hand circle](../pipelines/vfa/index.md#pose) was placed with (DWPose-l); in hand lengths, still is under 0.17 and active from 0.35.

**In the image, not against the shoulders.** Until the review of 2026-09-24 the wrists were followed against the midpoint of the shoulders, with the same bounds, and shoulders moving over hands that stayed put moved them, so a pupil who leaned in or turned with the hands resting on the table read as moving hands. In the image such a lean moves no wrist. That is the image's own cost: hands carried along with the body (a pupil shifting in the chair with the hands in the lap) move. An active step is the hands moving, whether the arm or the body moved them, not work on the artifact.

Per person: `_hand_steps` (steps with a status), `_hands_active_ratio` and `_hands_still_ratio` (of those), `_wrist_speed_sw` (the mean wrist speed, shoulder widths a second) and `_other_hands_near_ratio`: of the person's frames with a hand circle and a shoulder width, the share in which a hand circle of a body outside the group has its centre within one hand length (0.46 of the person's shoulder width) of one of theirs. A body counts as the group's own, not as someone else, when it wears a pupil's tag; when its box overlaps a pupil's by an IoU of 0.5 or more or lies 60 % or more inside it (a second skeleton, or an arm seen apart); when it has a hand centred within 0.1 shoulder widths of a pupil's (a shared wrist); when its box centre stands at a pupil's seat on that camera, the pupil seen there or not; or when it is on a track the server gave a pupil's tag to at some time of the session. What stays is not identified, since no frame is looked at, so a hit can still be a stray skeleton rather than the teacher or another group.

Per pair, over the steps in which both had a status on the same camera (`_hand_steps`): `_one_active_ratio` (one active, the other still), `_both_active_ratio`, `_both_still_ratio`, and `_follow_ratio`: of the one-active steps, given at least three, the share in which the still pupil's gaze at the step's end is on the active one's hands (their `partner_hands` target, or a gaze point in frame within reach of one of the active one's hand circles, the gaze tolerance included, unless the server found the still pupil's own hands nearer). A share of one or two steps could only be 0, 0.5 or 1. `_follow_ratio` says how much a still pupil's gaze was on a working partner's hands, not that the work drew it; the pupil's gaze on a partner's hands over the whole window is `_gaze_partner_hands_ratio`. Over the frames that hold both with a hand distance and both shoulder widths: `_hand_dist_sw_min` and `_hand_dist_sw_mean`, the hand distance over the mean of the two shoulder widths, and `_hands_close_ratio`, the share of those frames with the hands within one hand length. A column with nothing to judge is empty, never 0. Every step, like the wrist speed, is taken on one camera and the cameras are then pooled, each step counting once.

Two cameras that saw the same pupil on the same step can give it different statuses: a movement along one camera's line of sight is short in that camera's image, and each camera hides different wrists. The window's shares pool about nine steps a camera and are a noisy reading of a pupil's hands.

Limits. These are 2D positions from the pose model's wrists: hands close together are not hands touching, a hand at rest on the artifact can be working (fine manipulation with a still wrist reads still), hands carried along by a moving body read as movement (a lean over resting hands does not), and nothing here says what a hand holds. At one frame set a second a handover or a pointing stroke is seen once or not at all. Two cameras on one pupil can disagree on a step (above). The group's own bodies are told from others by boxes, seats and tracks: for `_other_hands_near_ratio` a teacher standing at a pupil's seat counts as the group, a stray skeleton away from the seats as someone else. For the joint split and `nm_*` (below) a teacher at the seat of a pupil in the frame is a non-member, and only a body at the seat of a pupil missing from the frame is taken for that pupil, so a teacher standing where an absent pupil sat still counts as the group. The whole-body model's hand lengths and centroids are an agreement between two models, not ground truth.

## Joint attention against its own past

Pupils who sit close look at the same table a lot, so the raw share of close gaze points partly measures seating. `pair<a>_<b>_joint_attention_baseline` compares each gaze point of a in the window (on a camera, in frame, at time t) with b's gaze point on the same camera at the frame set nearest t − d, within 0.5 s, for d = 20, 30 and 40 s, and the same with a and b swapped: a hit when the two lie within 5 % of the frame's width. The baseline is hits over comparisons, pooled over the cameras, the lags and both directions, and empty below 10 comparisons; `_joint_attention_excess` is the window's `_joint_attention_ratio` minus it. The lags sit past the decay of a joint episode and still within the same seating and task phase. Only b's points before the window are compared, whatever the window's length (a 60 s window would otherwise meet itself 20 s back), so the baseline is causal in time, but not in who a gaze point belongs to: that comes from the tags carried along the tracks over the whole session, where a track takes the tag of its nearest read even when that read comes later, and from seats learned from the whole session. So a badge read at minute 20 can change the baseline (and the partner/other split, like every tagged column) of a window at minute 18, and a server that keeps tags on tracks only forward would not reproduce these values exactly. The work area is not affected: it learns only from the tags the server gave, in time order. A joint episode that began 20 to 40 s earlier is part of the baseline: the excess measures change against the pair's recent level. The analysis record holds the constants (`work_area`, `joint_baseline`).

## Where joint attention met

Two gazes close together can be on the group's own table or on a teacher demonstrating at it. Since 2026-09-29 the fusion splits the joint attention of every pupil pair by what the gazes met (`window_features(..., joint_split=True)`, `mmla ses-fuse -js true`; off by default, so the default table is the one fused before it, byte for byte). First every frame's non-members are found: the bodies that wear no pupil's tag; are no second skeleton or part of a pupil (the tests of `_other_hands_near_ratio`: an IoU of 0.5, 60 % inside, a shared wrist); do not stand at the seat of a pupil missing from the frame, whatever tag they wear (a misread badge at its owner's seat is the owner); are on no track that carried a pupil's tag within 60 s; and are at least 0.6 of the pupils' size, their shoulder width against the median shoulder width of the pupils in the frame (else of the pupils on that camera over the session), or with their shoulders unseen their box width against the pupils' median box width. A smaller body is a far one, at the next table, and neither the group nor a non-member. A frame whose camera never saw a pupil's shoulders cannot tell, and has no non-members. Unlike `_other_hands_near_ratio`, a body at the seat of a pupil who is in the frame is not excused: a teacher leaning in beside a pupil is exactly who is meant. The 0.6 is fixed from geometry, not labels: a body at the group's depth reads about 1, one about 1.7 times as far from the camera 0.6 or less. The bound does not assume an adult reads larger than the pupils: a teacher standing behind the table can read a little smaller, and still passes.

Each pupil's gaze then has a referent. A gaze on someone else's face or hands (`other_face`, `other_hands`) is on an outsider when its target is a non-member (or the frame cannot tell), on the group when the target is the group's own by the rules above, and on nothing when it is a far body. A gaze point within reach of a non-member, within the gaze tolerance of one of their hand circles or of their face box grown by 20 %, is on an outsider whatever its label: the server gives a point to the nearest hand, so a teacher's hand beside a pupil's can leave the gaze named `partner_hands` or `own_hands`. Otherwise a partner's face or hands, the pupil's own hands and the work area are the group's own, and `elsewhere` and zones are nothing. A joint frame (the two gazes within 5 % of the width) is an outsider frame when either gaze is on an outsider, since two points that close are on the same thing, and a member frame when both are on the group's own; the rest (met elsewhere, in a zone, or on a teacher the pose model did not see) stays in `_joint_attention_ratio` only. `_joint_member_baseline` uses the baseline's comparisons, a hit counting only when both gazes were on the group's own things, so it keeps the meaning of the pair's own rate of meeting at their table. There is no outsider baseline: a demonstration lasts minutes, the gaze 20 to 40 s earlier is on the same teacher, and a baseline would absorb exactly the episode the column should show.

`nm_at_table_ratio` judges on each camera's table box, its work area as the last frame of the session holds it (offline, like the seats, so the first 40 to 60 s of a session, before the area is ready, are judged too), and grows it by one pupil shoulder width (about two hand lengths, an adult leaning in) for the body's box. `nm_hands_in_table_ratio` counts only hands inside the box itself, someone outside the group handling the group's artifact, and is the more specific of the two: a body standing near the table, a passer-by or a teacher watching, also reaches the grown box. A teacher the pose model missed, or one the rules take for the group (at an absent pupil's seat, on a pupil's track, overlapping a pupil's box), reads 0, not empty. The analysis record holds the constants (`joint_split`: the member labels, the outsider rule, `non_members` with `scale` 0.6, `table_reach_sw` 1.0, the table box, the track gap and the seat rule).
